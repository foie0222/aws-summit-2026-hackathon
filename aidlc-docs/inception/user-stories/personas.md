## P1: 永続ユーザー — タクヤ (30 代エンジニア)

| 属性 | 内容 |
|---|---|
| **仮名** | タクヤ |
| **年齢** | 33 歳 / 男性 |
| **職業** | フリーランス (副業) + 正社員 (本業) のソフトウェアエンジニア |
| **家族構成** | 妻 / 第一子の誕生を控える (出産直前) |
| **居住地** | 都市近郊 (実家・義実家とは別居) |
| **技術リテラシー** | 高 (Web / クラウドに親しんでいる) |

### 状況 (Context)
- 出産祝いを今後 1〜2 ヶ月で多数受領する立場。
- 結婚祝い・新築祝い・お年玉・香典といった贈答イベントが今後継続的に発生する。
- 普段から「半返し / 三分返し」のような文化ルールを毎回ググる手間を「些細だが地味に重い」と感じている。

### ニーズ / モチベーション
- 礼を尽くしながら、贈答に関わる作業時間を最小化したい。
- 親族や友人との関係を継続して保ちたい。
- 「あげる / もらう」の累計を後から見直して、抜け漏れや不公平を減らしたい。

### 痛み (Pain Points)
- マナーや相場の調査時間。
- 「誰から / いつ / いくらをもらったか」「誰に / いくらをあげたか」が記憶頼りで、抜けが起きる。
- 礼状や内祝いのカードを書く手間 (文面を都度ゼロから考える)。
- 贈答イベントの締切 (出産祝いの内祝いは生後 1 ヶ月以内など) を見落としがち。

### 利用頻度 / シーン
- 通常時: 月に数回 (新規イベント発生時)。
- 年末年始 / 季節イベント (お年玉 / お中元 / お歳暮): 集中利用。
- スマホ片手 + 自宅で利用するシーンが多い。

### 成功の定義
- 受け取った祝いに **取りこぼしなく内祝いを返せている** 状態。
- 翌年のお年玉や贈答計画を **過去履歴から自動で立てられる** 状態。
- ダッシュボードで **関係性の状態が一目で見える** 状態。

## P2: 来場者 — Summit ビジター

| 属性 | 内容 |
|---|---|
| **仮名** | Summit ビジター (集合体ペルソナ) |
| **属性** | AWS Summit 2026 来場者 (開発者 / IT 業界関係者中心) |
| **接触時間** | 3〜5 分 (ブース立ち寄り型) |
| **デモ時の立場** | **タクヤとしてプリセットされたデモアカウントに自動ログイン** (Q7=A) |
| **興味関心** | 生成 AI の活用事例 / マルチモーダル / ハッカソン作品の独自性 / テーマ整合性 |

### 状況 (Context)
- 多数のブースを巡回中で、立ち止まる時間は短い。
- 通路や周囲は騒がしい。スマホ / タブレット / 大型ディスプレイのいずれかで操作する。
- 「面白い」「短く価値がわかる」体験でないと離脱する。

### ニーズ / モチベーション
- 5 分以内で「何を解決するプロダクトなのか」を理解したい。
- 写真をアップする / ボタンを押す程度のシンプル操作で AI の挙動を体感したい。
- ハッカソンテーマ「人をダメにするサービス」への解答を、看板 (ポジティブキャッチ) と中身 (退化体感) のコントラストで掴みたい。

### 痛み (Pain Points)
- 操作が多いと離脱する。
- アカウント登録のような手続きを求められると体験を諦める。
- 中身が見えずに長い説明だけ流されると印象に残らない。

### 成功の定義
- 3〜5 分で **デモシナリオ S1 (内祝い)** を体験完了し、Receive ↔ Give 連携の見せ場を理解できる。
- 退出後に「のしを軽やかに、関係をずっと」というキャッチが残る。
- (余力時) S2 (お年玉) / S3 (Analytics ROI) のいずれか 1 つを追加体験する。
